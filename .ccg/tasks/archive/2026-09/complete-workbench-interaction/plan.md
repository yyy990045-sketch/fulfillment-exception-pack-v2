# 目标

参考 WALOVI Insight 的完整产品交互密度，把履约异常工作台从“一览/查证/处置展示”推进为可回看的业务工作流：每个进入、展开、提交、退回、回执和结案动作都有明确反馈、状态变化和下一步。

# 第一阶段（先实现，范围可验收）

1. 案件详情：在现有三层工作台中补齐案件摘要、当前阶段、状态、返回路径和空/失败状态。
2. 证据抽屉：点击差异卡打开抽屉，展示报价、订单、回款、客诉相关原文、来源和定位；支持关闭、键盘 Escape 和移动端全屏。
3. 差异状态：新增前端/后端“待核对、已核对、需补材料”状态，统计数字和卡片即时更新，刷新后保留。
4. 方案表单：在处置页提供动作、负责人、完成条件、依据字段；提交前校验，提交后变为待负责人确认。
5. 审批反馈：确认、退回、补材料三个结果均有确认框、Toast、时间线和状态更新。
6. 结果表单：填写结果说明、回执文本和附件元信息；执行前后明确显示处理结果，支持安全失败。

# 第二阶段（在第一阶段稳定后）

- 完成/撤销执行与效果回写视图；
- 按角色显示待办和负责人；
- 详情页的页签、历史版本和筛选；
- 将系统告警作为独立入口，不进入销售履约队列。

# 不做

- 不接真实 CRM、审批系统或生产回单；
- 不把合成回执写成真实业务结果；
- 不复制 WALOVI 的市场数据、品牌文案或无关模块。

# 验收标准

- 每个按钮都有可观察反馈；
- 刷新后状态与时间线一致；
- 证据抽屉不泄露内部租户/追踪标识；
- 未审批不可执行，缺回执不可结案；
- 桌面、平板、手机无页面级横向溢出；
- `npm test`、`npm run typecheck`、`npm run eval` 全部通过。
