# 企业落地差距与最小应用路径

定位：发车前辅助决策，先可解释检查，再由调度员确认。当前所有城市配送数据均为合成；正式终赛及企业数据尚未取得。旧制造业连接器不能作为已接通配送ERP/WMS/TMS的证据。

## 数据对应关系

| 业务来源 | 当前字段 | 企业侧需要的数据 | 当前差距/责任 |
|---|---|---|---|
| ERP/OMS 订单与客户 | stops.stopId/name；cargo.stopId/cargoId | 实际订单号、客户号、配送日期、地址、数量、订单拆合关系 | 当前没有正式orderId/订单生命周期；需要OMS负责人提供脱敏批次、唯一关联及取消规则 |
| ERP/OMS 配送要求 | timeWindow、serviceDurationMinutes、departureTime | 收货时间、预约、服务时长、优先级、到店 vs 服务开始口径 | 合成时窗；人工/客户确认。当前时窗按服务开始，不保证服务结束仍在窗内 |
| WMS 包装件 | cargoId、length/width/height、weightKg | 包装级实测尺寸/重量、包装数量、是否可旋转、扫描标识 | 通常SKU尺寸不等于最终箱规；需仓库实测或包装主数据，不可缺值当0 |
| WMS 作业限制 | fragile、maxTopLoadKg、orientation、handlingRequirements | 包装承重、托盘/箱体、禁混装、可用工具、可抽取方向 | 易碎/承重缺失时需要人工维护；当前两层100%支撑规则需仓库负责人签认 |
| TMS 车辆与车厢 | vehicleId、maxPayloadKg、compartment、rearDoor | 实际车型、净空间、轮包、门净开口、货舱分隔、可用日期与司机 | 当前是合成箱体和外观示意；需车辆管理员测量，不能用车辆外部尺寸替代 |
| TMS 路线时间 | warehouse、stops.x/y、distanceMatrixKm、travelTimeMatrixMinutes | 地址地理编码、道路距离、分时段行车时间、禁行/限高 | 当前合成正交街区，无地图服务或实时交通；实际道路服务待验证 |
| TMS 业务成本 | vehicles[].costs、waitingCostPerMinute | 启车费、里程/时间成本、路桥、司机、等待、装卸、重装 | 当前计划成本是假设；需运营财务确认，不直接用于企业ROI |
| TMS 执行与回执 | route、placements、unloading.steps、前端startedPlan | 计划版本、下发接收、司机确认、装车复核、回单、到店异常 | 目前只有模拟播放和内存确认；没有企业下发、GPS或回单闭环 |

## 必须人工确认的节点

1. 调度员确认订单与客户收货约束、出发时间、是否允许重新分配。
2. 仓库负责人确认箱规、朝向、易碎、承重、实际取货规则与车厢有效空间。
3. 系统给出候选和失败原因；调度员确认采用。页面确认当前仅会话内有效，不能替代企业审计记录。
4. 装车人员按最终布局检查实车，若不一致回退人工处理，不能由动画自动批准。
5. 只有真实接入验证和业务授权完成后才允许下发TMS/司机；本系统当前没有此下发能力。

## 部署依赖与运行责任

| 部分 | 当前实际情况 | 最小责任与后续验证 |
|---|---|---|
| 页面 | React/Vite，本机8111，现有三维模型；需要支持WebGL的浏览器 | 产品演示负责人维护正式入口、分辨率和两段录屏备份 |
| 计算 | 本机8112，隔离Python环境、OR-Tools9.11.4210；单线程 | 本机运行负责人启动/检查服务。真实场景前再评估是否需要部署变更，不先建生产平台 |
| 数据 | public/demo目录，固定场景，只接受两个scenarioId | 数据负责人提供版本、校验和、单位、来源；正式数据不能直接塞进公开静态目录 |
| 路由代理 | Vite将/api/city-delivery转发8112；健康检查直接访问8112 | 远程部署需重新验证健康/计算代理和来源许可；当前只证明本机可用 |
| 运维 | 没有生产进程托管、容量/可用性承诺 | 比赛用启动检查即可；企业试点另行界定失败回退和责任，不将演示误作SLA |

## 权限与隐私

当前无真实客户数据，本机回环访问及受限来源降低本地暴露，但不是企业权限隔离。公开静态目录中的数据浏览器可读，不能放真实客户地址、联系方式、路线或报价。无用户/组织权限、审计、持久计划确认，禁止以此宣称安全合规完成。

企业样本先脱敏：订单/客户/车辆映射使用稳定匿名ID；尺寸与重量保留真实数值；地址转换为已授权道路矩阵；报价以授权口径使用。原始客户与标识映射由企业保管。本轮未向外部模型或网站发送项目数据。

## 异常与计划下发边界

- 数据缺失/单位不明：拒绝批准或转人工确认，不补造尺寸、重量或时间窗。
- 当前方法装不下：返回具体规则和受影响货物，尝试授权范围内换车；“未找到布局”不等于所有方法数学无解。
- 路线与时窗不满足：布局有效也必须保持不可执行；允许调度员修改发车前条件后再检查。
- 服务失败：保留已确认方案，禁用即时调整；是否执行已确认方案由现场负责人决定，不依赖模拟动画。
- 发车后故障：当前不支持在途自动重装或现场自适应；由现有TMS和调度员处理，不按重新规划动画冒充实车作业。

## 最小企业试点路径（规划，不是本轮实施）

| 阶段 | 必需产物 | 放行依据 |
|---|---|---|
| 资料核对 | 一份脱敏真实批次、真实箱规、两种实际车厢、收货窗与费用口径 | 企业数据/仓库/调度负责人确认来源、单位和限制 |
| 离线辅助 | 用真实批次输出计划，与原调度计划比较；保持现有系统实际执行 | 按同订单/资源/约束检查可执行性，记录差异和人工处理时间，不捏造收益 |
| 实车验证 | 少量车辆装卸演练，记录阻挡、人员空间、耗时及货损风险 | 装卸负责人确认可执行；必要时只补真实缺失规则 |
| 有限应用 | 经授权的计划版本导出或企业系统接收，不直接替换生产调度 | 明确人工批准、撤回、异常回退和下发回执责任 |

正式路演前最需要补的现场证据：脱敏批次来源、实车净空间与箱规核对、装卸人员对直线取货/支撑规则的确认。尚未取得，标记待验证。

不建议本轮增加数据库、Agent、监控平台或大规模实验。先验证实际作业规则和数据可取得性；这些决定是否需要修改规则，工程规模并不能替代现场事实。
